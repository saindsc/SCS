- In-depth article viewing with related content
- Social sharing capabilities
- Author credentials display
- Rich content formatting support

Technology Stack:
- Framework: Next.js (React)
- Styling: Tailwind CSS
- Animations: Framer Motion
- Language: TypeScript
- Image Handling: Next.js Image component

3. DATA ARCHITECTURE
====================

BlogPost Interface Structure:
-----------------------------
{
  id: number
  slug: string (URL-friendly identifier, e.g., "infertility-and-suicide-breaking-the-silence")
  title: string (Display heading for article)
  excerpt: string (Short summary, <200 characters)
  content: string (Main article body - markdown-style format)
  author: string (Writer name)
  authorRole: string (Professional credential/title)
  date: string (ISO format YYYY-MM-DD)
  readTime: string (Estimated read duration, e.g., "6 min read")
  category: string (One of: mental-health, relationships, wellness, parenting, self-care)
  tags: string[] (Array of related topic tags)
  image: string (Feature image - path, URL, or emoji)
  additionalImages?: string[] (Optional gallery images)
  featured: boolean (Display in featured section on main blog page)
}

Blog Categories:
----------------
All
├── Mental Health (id: mental-health)
├── Relationships (id: relationships)
├── Wellness (id: wellness)
├── Parenting (id: parenting)
└── Self-Care (id: self-care)

Content Format Reference:
-------------------------
The content field uses markdown-style formatting that is parsed by renderContent():

## Heading Level 2
### Heading Level 3
**Bold Text (on own line)**
- Bullet point
  (Renders as unordered list)
1. Numbered item
  (Renders as ordered list)
Regular paragraph text

Example article structure:
- Intro paragraph
- ## Main Topic Heading
- Several body paragraphs
- ### Subtopic
- More paragraphs
- - Bullet points with details
- ## Another Section
- Conclusion

4. COMPONENT DETAILS
====================

A. BlogPostContent.tsx
======================
File: app/blog/[slug]/BlogPostContent.tsx
Type: Client-side Component ('use client')
Lines: 448

Imports:
- React hooks
- motion from framer-motion
- Link from next/link
- Image from next/image
- Icons from lucide-react (Calendar, Clock, User, Share2, ArrowRight, Tag)
- blogCategories from config

Key Functions:
--------------
1. isLocalImage(value: string) → boolean
   Purpose: Detect if image is a local file path
   Returns: true if path starts with "/"

2. isRemoteImage(value: string) → boolean
   Purpose: Detect if image is a remote URL
   Returns: true if URL starts with "http://" or "https://"

3. renderContent(content: string) → React.ReactNode[]
   Purpose: Parse markdown-style content and return JSX elements

   Parsing Rules:
   - Empty lines: <div className="h-4" /> (spacing)
   - "## " prefix: h2 element
   - "### " prefix: h3 element
   - "** **" wrapped: bold paragraph
   - "- " prefix: list item
   - "N. " prefix: numbered list item
   - Other: regular paragraph

4. handleShare() → Promise
   Purpose: Share article via browser Share API or clipboard
   Behavior:
   - Try navigator.share() if available
   - Fallback to clipboard.writeText()
   - Show user notification

Component Props:
----------------
interface BlogPostContentProps {
  post: BlogPost
  relatedPosts: BlogPost[]
}

Usage in Route:
- Receives post data from route handler
- Receives related posts array (typically same category, different article)

Styling Approach:
- Tailwind CSS utility classes
- Responsive breakpoints: sm, md, lg
- Color tokens: primary-500, purple-600, gray-900, white, etc.
- Gradients for visual emphasis
- Drop shadows for depth

Animations:
- Motion divs with fadeInUp pattern
- Initial { opacity: 0, y: 30 }
- Animate { opacity: 1, y: 0 }
- whileInView for scroll-triggered animations
- whileHover for interactive elements

B. BlogPage (page.tsx)
======================
File: app/blog/page.tsx
Type: Client-side Component ('use client')
Lines: 262

State Management:
- selectedCategory: string (user's category filter, default: "all")

Data Loading:
- blogPosts: imported array of all posts
- blogCategories: imported array of categories
- featuredPosts: computed from getFeaturedBlogPosts()
- filteredPosts: computed based on selectedCategory

Filtering Logic:
```
Normalize selected category: trim().toLowerCase()
If normalized = "all": return all posts
Else: return posts where category.trim().toLowerCase() === normalized
```

Rendering:
1. Hero Section (60vh)
   - Background gradient
   - Centered text content
   - Icon badge
   - Main heading
   - Subheading

2. Featured Posts (3 columns)
   - Uses getFeaturedBlogPosts()

   - Links to /blog/{slug}

3. Category Filter (horizontal buttons)
   - 6 buttons (one per category)
   - onClick updates selectedCategory
   - Conditional styling for active state

   - Inactive button: gray background

4. All Posts Grid
   - Responsive columns: md:2, lg:3
   - Filtered based on selected category

5. CTA Section

2. See featured articles (3 most important)

4. Browse filtered articles in grid
5. Click on article to read full content

- Related articles shown for discovery

6. CONTENT MANAGEMENT
=====================

Adding New Articles:
---------------------
1. Add entry to blogPosts array in lib/blog-data.ts
2. Follow BlogPost interface structure
3. Use markdown-style formatting for content
4. Set featured: true/false appropriately
5. Ensure unique slug (URL-friendly identifier)
6. Select from existing categories
7. Add author and authorRole
8. Set read time estimate
9. Create tags array for discoverability
10. Upload feature image (or use emoji)

Content Best Practices:
- Titles: 50-60 characters (SEO, readability)
- Excerpts: 150-200 characters
- Content: Use ## headers for sections
- Tags: 3-5 relevant tags per article
- Images: Use local paths (/images/...) where possible
- Read Time: ~250 words per minute
- Author: List credentials (e.g., "Ph.D in Psychology")

Updating Existing Articles:
1. Find article by slug in blogPosts
2. Edit content field
3. Update date if significant changes
4. Maintain featured flag
5. Test rendering on /blog/{slug}

Modifying Categories:
1. Edit blogCategories array in blog-data.ts
2. Update category IDs in articles
3. Ensure no articles reference deleted categories
4. Update page.tsx filtering logic if needed

Image Management:
- Local images: Store in /public/images/
- Subdirectories: /public/images/blog/ for blog-specific images
- Formats: PNG, JPG, WebP supported
- Sizing: Use Next.js Image component for optimization
- Fallback: Use emoji for quick implementation

MAINTENANCE NOTES
=================

Regular Tasks:
- Review article dates quarterly
- Update featured articles seasonally
- Monitor for broken image links
- Check external links in content
- Update author credentials when needed
- Archive outdated mental health advice

Performance Considerations:
- Image lazy loading enabled
- Content parsing done at render time (consider memoization for large articles)
- Category filtering is O(n) where n = total articles
- Consider pagination if articles exceed 50+

Accessibility:
- All images have alt text
- Heading hierarchy maintained (h1 → h2 → h3)
- Color contrast meets WCAG standards
- Links have meaningful text
- Share button has proper labels

SEO Optimization:
- Each article is individual page (crawlable)
- Meta descriptions in excerpts
- Structured headings for content outline
- Internal links to related articles
- Author credentials for E-A-T (Expertise, Authoritativeness, Trustworthiness)

ERROR HANDLING:

If article slug not found:
- Route handler should show 404
- Fallback to blog listing

If image fails to load:
- Next.js fallback gray placeholder
- Emoji fallback displays

If no articles in category:
- Show "No articles found in this category" message
- Suggest browsing all articles

If renderContent() encounters edge case:
- Falls back to rendering as paragraph
- No blank content sections
